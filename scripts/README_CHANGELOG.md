# Автоматизированное ведение Changelog

## 📋 Описание

Система автоматизированного ведения changelog продукта, которая позволяет:
- Добавлять записи о изменениях в продукт (вы предоставляете текст)
- Автоматически генерировать красивый CHANGELOG.md для публикации пользователям
- Вести историю изменений по версиям в формате [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/)

## 🚀 Быстрый старт

### 1. Добавить новую запись в changelog

```bash
python scripts/changelog_manager.py add <версия> --message "Ваш текст изменения" [--type тип]
```

**Параметры:**
- `<версия>` - номер версии (например, `1.0.0`, `2.1.3`)
- `--message` - текст изменения (который вы предоставляете)
- `--type` - тип изменения (опционально, по умолчанию `added`)

**Типы изменений:**
- `added` - добавлено новое
- `changed` - изменено существующее
- `deprecated` - устарело
- `removed` - удалено
- `fixed` - исправлено
- `security` - безопасность

**Примеры:**

```bash
# Добавить новое функциональное улучшение
python scripts/changelog_manager.py add 1.1.0 --message "Добавлена поддержка OAuth2 аутентификации"

# Добавить исправление бага
python scripts/changelog_manager.py add 1.1.0 --message "Исправлена ошибка при обработке JWT токенов" --type fixed

# Добавить информацию об устаревшем API
python scripts/changelog_manager.py add 1.2.0 --message "API v1 помечено как устаревшее" --type deprecated
```

### 2. Сгенерировать CHANGELOG.md для публикации

```bash
python scripts/changelog_manager.py generate
```

После выполнения команды в корне проекта появится файл `CHANGELOG.md`, который можно публиковать для пользователей.

### 3. Просмотреть текущий changelog

```bash
python scripts/changelog_manager.py show
```

## 📁 Структура файлов

```
/workspace
├── scripts/
│   └── changelog_manager.py    # Основной скрипт управления changelog
├── changelog.json              # Исходные данные changelog (хранит всю историю)
└── CHANGELOG.md                # Сгенерированный файл для публикации (создается автоматически)
```

## 📝 Рабочий процесс

1. **Вы готовите текст изменения** - описываете что изменилось в продукте
2. **Добавляете запись** - выполняете команду `add` с вашей версией и текстом
3. **Генерируете публикацию** - выполняете команду `generate` перед релизом
4. **Публикуете CHANGELOG.md** - используете сгенерированный файл для пользователей

## 🔧 Дополнительные возможности

### Несколько записей в одной версии

Вы можете добавить несколько записей в одну версию:

```bash
python scripts/changelog_manager.py add 1.0.0 --message "Первый релиз" --type added
python scripts/changelog_manager.py add 1.0.0 --message "Исправлен баг авторизации" --type fixed
python scripts/changelog_manager.py add 1.0.0 --message "Улучшена производительность" --type changed
```

Все записи будут сгруппированы по типам в финальном CHANGELOG.md.

### Формат выходного файла

Сгенерированный `CHANGELOG.md` имеет следующий формат:

```markdown
# Changelog

Все заметные изменения в проекте будут документироваться в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и этот проект придерживается [Семантического Версионирования](https://semver.org/lang/ru/).

## [1.0.0] - 2026-04-04

### Добавлено
- Первый релиз проекта arch-labs

### Исправлено
- Исправлена ошибка авторизации в JWT модуле

[1.0.0]: https://github.com/your-org/arch-labs/releases/tag/1.0.0
```

## 💡 Рекомендации

1. **Добавляйте записи сразу** - как только изменение внесено в код, сразу добавляйте его в changelog
2. **Пишите понятно** - текст должен быть понятен конечным пользователям
3. **Группируйте по версиям** - все изменения одного релиза добавляйте с одинаковым номером версии
4. **Генерируйте перед релизом** - запускайте `generate` перед каждым публичным релизом

## 🎯 Интеграция с GitHub Releases

Для автоматической публикации changelog в GitHub Releases можно использовать GitHub Actions.
Пример workflow находится в `.github/workflows/`.
